# Master tables

Three CSVs, one per grain, regenerated by `make masters`
(`python -m export.masters`). All are **PRELIMINARY** per D6: the exposure
scores behind them are LLM-only and the human-validation kappa gate has not
cleared, so nothing here may enter the abstract or the paper.

| File | Grain | Rows |
|---|---|---|
| `outputs/tables/task_master_PRELIMINARY.csv` | one NCO task statement | ~18.6k |
| `outputs/tables/occupation_master_PRELIMINARY.csv` | one NCO 3-digit group | 122 |
| `outputs/tables/sector_master_PRELIMINARY.csv` | one NAS activity head | 8 |
| `outputs/tables/masters_PRELIMINARY.meta.json` | build provenance, coverage, EPFO allocation | — |

## Why three files and not one

The sources sit at three different grains, and occupations span sectors. A
single flat row saying "this task belongs to an occupation with 4.2M workers
producing ₹X of GVA and Y net EPFO additions" would require an allocation rule
this project does not have — that is a fabricated number, not a join
(Golden Rule 1). What can be joined is published as keys:

- `task_master.group3` → `occupation_master.group3`
- `task_master.nco_code` → the 8-digit occupation index
- `occupation_master` → `sector_master`: **no key.** The only honest link
  between an occupation and an industry is the worker-level PLFS file
  (`data/processed/plfs_exposure_PRELIMINARY.parquet`), where each worker
  carries both. Ask that file, not these two.

## task_master

| Column | Meaning |
|---|---|
| `task_id` | `{nco_code}-t{NN}`, NN indexing sentences within the occupation |
| `nco_code` | NCO-2015 8-digit occupation |
| `division1`, `sub_division2`, `group3`, `family4` | the nested code hierarchy (1/2/3/4 digits) |
| `occupation_title` | official Vol II title (8-digit level) |
| `group3_label` | **editorial** label from `atlas_common.nco_labels`, not the official NCO title; blank where we have not written one |
| `task_text` | the task statement as scored |
| `scored`, `score`, `exposed` | whether the task got a score; E0/E1/E2; `exposed` = E1 or E2 |
| `occupation_n_tasks`, `occupation_beta` | 8-digit index |
| `group3_n_tasks`, `group3_alpha/beta/zeta` | 3-digit index (α = E1 share, β = E1 + ½E2, ζ = E1 + E2) |
| `rubric_version`, `model`, `n_samples`, `preliminary` | scoring provenance |

Unscored tasks are kept with `scored = false` rather than dropped, so the
parsed → scored → classified waterfall is auditable from this file alone.

**Known gap:** official titles exist only at the 8-digit level. NCO-2015
Vol I carries the titles for division / sub-division / group / family, and has
no parser yet — those levels ship as codes.

## occupation_master

One row per 3-digit group: the index (`alpha`, `beta`, `zeta`, `e2_share`,
`n_tasks`, `high_exposure` = β ≥ 0.5), the typology cluster and its name, and
the PLFS 2023-24 block — `workers_m`, `n_records`, `employment_share`,
`mean_alpha/beta`, `high_exposure_share`, `median_monthly_earnings_inr`,
`mean_monthly_earnings_inr`, `monthly_wage_bill_inr_m`, `wage_bill_share`,
`earner_share`, `female_share`, `urban_share`, `grad_share`, `young_share`,
`formal_proxy_share`.

`grad_share` is education codes 12–13 — graduate or postgraduate, nothing
below (`atlas_common.education.GRADUATE_PLUS`). It does **not** include higher
secondary or diploma holders.

Every PLFS statistic is survey-weighted (`weight = mult/no_qtr`). Three
definitions to read carefully:

- **Earnings** are salaried + self-employed monthly earnings. Casual daily
  wages are not folded in yet (see `merge.plfs`), so levels understate
  wherever casual work is common.
- **Medians and means** are over earners (`monthly_earnings > 0`);
  `earner_share` tells you what fraction of the group that is. Wage-bill
  columns are over everyone, with non-earners contributing zero.
- **`formal_proxy_share`** is a social-security-benefit proxy, computed over
  records where the benefit code is informative — "not known" is excluded from
  the denominator rather than counted as informal.

## sector_master

One row per NAS activity head (`atlas_common.sectors`), always all 8 — a head
with no matched workers keeps its GVA row with null PLFS columns.

- `gva_crore_fy2023_24`, `gva_share` — NAS Statement 4A, FY2023-24 FRE,
  current prices, ₹ crore.
- `nic2_divisions` — the NIC-2008 divisions that define the head. Disjoint
  across heads, so each worker lands in at most one.
- PLFS block — same columns as `occupation_master`, but shares are of
  **matched** employment (workers with a usable NIC division), not of national
  employment. The unmatched fraction is in the meta JSON.
- `epfo_net_payroll_window`, `..._age_le25`, `epfo_heads_mapped` — EPFO net
  payroll (net of exits; negatives are legitimate) over the latest 12 months
  present in the payroll panel, and the ≤25 age bands within it.

**EPFO allocation rule.** EPFO industry heads are establishment classes, not
NIC divisions, and the hand-authored crosswalk's division sets overlap. A head
is credited to a NAS head only when *every* division it maps to sits inside
that NAS head; a head straddling two (engineering contractors: NIC 33, 42, 71)
is left unallocated and reported in the meta JSON with its share of absolute
volume — never split. Splitting would need a payroll-share assumption we do
not have. Expect the unallocated share to be large; that is the honest state
of the mapping, and it is why EPFO is a column on a sector row rather than a
number attached to an occupation.
